# 부동산 매물 홍보 모드 기획 (초안, 2026-11-04)

'우리 가게 홍보'(D21 소상공인 모드)와 같은 방식으로, 공인중개사가 매물 사진과 정보를 넣으면 30초 세로 매물 소개 영상(MP4 + SRT)과 업로드용 설명란·체크리스트를 만든다. 비용 ₩0 기본 경로, 로컬 설치형이라는 원칙은 그대로다.

> 상태(2026-11-04): 사용자 '진행'으로 추천안 확정(D-1 중개사 전용, D-2 주거용, D-3 AI 영상 끔(2026-11-06 사용자 결정으로 허용으로 바꿈, DECISIONS D23), D-5 커버에 가격 넣지 않음, D-7 1건씩). L0~L5 1차 구현 완료(DECISIONS D23). 남은 것(2026-11-06 매물 정보 고치기·훅 되풀이 줄이기 완료): 가격만 바뀔 때 LLM 없이 가격 대사만 바꾸기, 고시 '명시사항 세부기준' 현행 원문 확인, D-4 소재지 공개 범위 확정, 실제 Gemini로 매물 3건 대본 Gate(L3), 실제 매물 사진으로 끝까지(L6), 상업 이용 약관(D-6).

## 1. 왜 비슷한 방식인가

가게 홍보에서 배운 것이 부동산에는 더 강하게 적용된다.

| 가게 홍보에서 배운 것 | 부동산에서 | 그래서 |
|---|---|---|
| 틀린 가격·혜택은 사장님 이름의 허위 광고가 된다 | 가격·면적·층·관리비가 틀리면 **부당한 표시·광고**(공인중개사법 제18조의2)로 과태료 대상 | 숫자가 들어가는 대사·자막은 AI가 쓰지 않고 입력값을 코드로 넣는다 (`fix_shop_lines` 방식) |
| AI가 음식·가짜 간판을 그렸다 | AI가 방을 그리거나 넓혀 보이게 하면 '사진을 거짓으로 표시'한 광고 | 그림은 실제 사진만. AI 영상도 기본은 끈다(결정 필요 D-3) |
| 입력에 없는 인기·과장 표현을 지어냈다 | "역세권 1분", "최저가", "투자 가치 보장", 입력에 없는 학교·역 거리 | `fact_problems`처럼 입력에 없는 숫자·거리·과장어를 막는다 |
| 사장님이 고친 가게 정보를 다음 영상에 다시 쓴다 (`shops.json`) | 중개사무소 정보는 매번 같다 | 사무소 정보는 한 번 저장(`offices.json`), 매물만 새로 넣는다 |

## 2. 사용자와 흐름

**사용자:** 개업공인중개사(1인~소규모 사무소). 매물이 자주 바뀌고 같은 형식으로 여러 개를 만든다.

**흐름(쉬운 화면 3단계 유지):**
1. 홈 → **'매물 홍보'** 카드(설정에서 켤 때만, 가게 홍보와 같은 시험 기능)
2. **매물 입력 양식** — 사무소 정보는 저장된 것을 고르고, 매물 정보와 사진만 넣는다
3. ① 아이디어(자동) → ② 다듬기(대사·음악·목소리, 사진 순서) → ③ 완성(영상 + **필수 표시 확인** + 설명란)
4. (2차) 같은 사무소의 매물 여러 개를 차례로 만드는 '이어서 만들기'

## 3. 법령에서 오는 요구 (확인 필요)

검색으로 확인한 내용(원문·유권해석 확인 전, 구현 전에 반드시 다시 본다):

- **명시 의무(제18조의2 제1·2항):** 중개대상물을 표시·광고할 때 중개사무소·개업공인중개사 정보(사무소 명칭, 소재지, 연락처, 등록번호, 개업공인중개사 성명)와 중개대상물 정보(소재지, 면적, 가격, 종류, 거래 형태, 건축물이면 총 층수·사용승인일·방향·방/욕실 수·입주 가능일·주차·관리비 등)를 명시해야 한다. 위반은 과태료(검색 자료상 100만원 이하).
- **중개보조원 정보는 넣으면 안 된다.**
- **부당한 표시·광고 금지(제18조의2 제4항, 국토부 고시):** 없는 매물(허위), 가격·면적·평면도·사진을 거짓으로 표시하거나 과장, 입지·생활 여건을 숨기거나 줄이는 광고. 검색 자료상 500만원 이하 과태료.
- **거래가 끝난 매물 광고는 내려야 한다**(늦게 내려 과태료를 받은 사례가 있다).
- **모니터링:** 한국인터넷광고재단이 인터넷 광고를 모니터링하고 지자체에 처분을 요구한다.
- **확인하지 못한 것:** YouTube 숏폼 영상에서 명시사항을 '어디에 얼마나' 보여야 충족하는지(영상 안 표시 vs 설명란). 그래서 **두 곳 모두** 넣는 쪽으로 설계한다.

## 4. 기능 설계 (기존 구조에 대응)

### 4.1 모드와 입력

- `Input.mode`에 `"listing"`을 더한다. 만들 때 정하고 바꿀 수 없다(가게 모드와 같은 `_apply_edit` 보호).
- `app/modes.py`에 `LISTING = ModeProfile("listing", world_search=False, strategy_overlay="s4_listing")`.
- **사무소 정보** `OfficeProfile` (`data/offices.json`, `GET·POST /offices`, 만들 때 프로젝트로 복사): 사무소 명칭, 소재지, 연락처, 등록번호, 대표 공인중개사 성명. 중개보조원 칸은 두지 않는다.
- **매물 정보** `ListingBrief`:

| 칸 | 예 | 쓰는 곳 |
|---|---|---|
| 종류 | 아파트·오피스텔·빌라·원룸·상가·사무실·토지 | 대사·검색어·필수 표시 |
| 거래 형태 | 매매·전세·월세 | 가격 장면·필수 표시 |
| 가격 | 매매가 / 보증금 / 월세 | 가격 장면(코드가 넣음) |
| 소재지 공개 범위 | '○○동'까지 / 단지명까지 | 대사·필수 표시 (동·호수는 넣지 않는 것을 기본) |
| 면적 | 전용 ㎡ (공급 ㎡) | 필수 표시 (대사에서 평 환산은 코드가 계산해 함께 표시) |
| 층 / 총 층수, 방향, 방·욕실 수 | 7층 / 15층, 남향, 방 3 욕실 2 | 필수 표시, 장면 대사(코드) |
| 사용승인일, 입주 가능일, 주차, 관리비 | 2015.03, 즉시, 1대, 15만원 | 필수 표시 |
| 중개사가 직접 쓴 장점 | "거실 통창, 리모델링 2024" | 대본의 유일한 근거 (`pride`와 같은 역할) |
| 주변 정보(선택) | "○○초 도보 5분" | 입력에 있을 때만 대사에 쓸 수 있다 |
| 손님이 할 일 | "문자로 방문 예약" | 마지막 대사(코드) |

- 입력 확인(`shop_check` 재사용): 맞춤법 제안 + **빠진 필수 항목 되묻기**(코드). 예: 건축물인데 사용승인일이 없으면 "사용승인일을 적어 주세요".

### 4.2 대본 (S4)

- `prompts/s4_listing.md`: 중개사 1인칭, 과장 금지, 입력에 없는 숫자·거리·시설 금지.
- **AI가 쓰지 않는 장면:** 가격 장면(`offer` 역할 재사용 → "전세 3억 2천, 즉시 입주 가능해요")과 마지막 장면(cta). `fix_listing_lines()`가 입력값으로 넣는다.
- **검사(`listing_problems`, `fact_problems` 확장):** 입력에 없는 숫자·금액·면적·층·거리, 금지 표현 목록("최저가", "급매"(입력에 없을 때), "수익 보장", "투자 가치", "로열층", "역세권"(주변 정보에 역이 없을 때), "실거래가보다 싸게" 등). 3회 뒤에도 남으면 경고로 보여 주고 고칠 대사만 표시한다(가게와 같은 방식).
- 대사 늘리기는 쓰지 않는다(입력에 없는 장점이 들어간다).
- 장면 역할 배정: hook(전경·가장 좋은 공간) → method(거실·주방·방) → payoff(장점·뷰) → offer(가격) → cta.

### 4.3 사진 (S5)

- **실제 사진만**(가게 모드의 `scene_media()` 구조 재사용). AI 그림·무료 사진·무료 영상은 막는다(`real_photos_only` 재사용).
- 사진 종류 `media_kinds`를 매물용으로: 외관·거실·주방·방·욕실·뷰·평면도·기타. `ROLE_PHOTOS`로 역할별 배정.
- 정사각형·가로 사진은 렌더의 흐린 배경 맞춤(`_fit`)으로 잘리지 않게(이미 있음: 실내 사진은 가로가 많다).
- **AI 영상:** 기본은 끈다(결정 필요 D-3). 가게 실측에서 AI가 장면을 바꾸고(신발 모양), 정사각형은 양옆 44%가 잘렸다. 방 크기·구조가 달라 보이면 '사진을 거짓으로 표시'에 가깝다.
- **개인정보:** 사진 고를 때 "거주자 얼굴·우편물·차량 번호·가족사진이 보이지 않나요?"를 한 번 확인(체크리스트에도). 렌더는 메타데이터를 넣지 않는다(위치 정보 없음).

### 4.4 렌더·필수 표시 (S7)

- **매물 정보 카드:** 영상 끝 3~4초에 필수 표시 항목을 화면에 띄운다(`modes.end_card()` → `subtitles.end_card_cues()` 확장, 여러 줄 작은 글씨). 사무소 명칭·등록번호·연락처·대표 성명 + 매물 소재지·면적·가격·종류·거래 형태·층·사용승인일 등.
- 항목이 많아 한 화면에 넘치면 2장으로 나눈다(자막 폭 검사 `too_wide()` 재사용). 렌더 점검(`render_checks`)에 '필수 표시 카드 있음'을 더한다.
- 커버(썸네일)는 매물 종류 + 거래 형태 + 동네('○○동 전세 32평')로. 가격을 커버에 넣을지는 결정 필요(D-5).

### 4.5 업로드 도구

- `listing_checklist()`: 필수 표시 항목이 실제와 같다 / 매물이 지금 거래 가능하다(허위 매물 아님) / 사진이 이 매물의 최근 사진이다 / 사진에 개인정보가 없다 / **거래가 끝나면 영상을 내리거나 비공개로 바꾼다** / 중개보조원 정보를 넣지 않았다 / 상업 이용 약관(Edge 음성·Gemini 무료 등급) 확인.
- `listing_description()`: 설명란에 필수 표시 항목 전체를 글로 넣는다(영상 카드와 같은 내용).
- (2차) 홈 목록에 '거래 완료' 표시와 "이 영상 내리셨나요?" 알림.

### 4.6 참고 영상 (S1~S3)

- 해외 검색 끔. 검색어는 '○○동 아파트 매물 소개', '전세 룸투어', '오피스텔 랜선 집들이'처럼 종류·거래 형태 중심(가게 이름을 빼던 `shop_keywords()`처럼 단지명·주소는 검색어에서 뺀다).
- 참고 영상이 없을 때의 막다른 길은 가게 모드와 같은 결정 대기 항목('참고 영상 없이 진행')을 함께 정한다.

## 5. 재사용과 새로 만들 것

| 재사용 (그대로) | 일반화해서 재사용 | 새로 |
|---|---|---|
| 렌더·음성·자막·음악·다듬기 화면, 실패 안내, 업로드 화면 틀, 사진 업로드·종류 고르기·흐린 배경 맞춤, `real_photos_only`, 입력 확인(맞춤법) | `BusinessBrief`→ 모드별 brief, `fix_shop_lines`·`fact_problems`·`end_card`·`shop_checklist`·`ROLE_PHOTOS`·`shops.py`(→ 사무소) | `ListingBrief`·`OfficeProfile`, `s4_listing.md`, 금지 표현 목록, 매물 정보 카드(여러 줄), `ListingForm.tsx`, 매물 체크리스트·설명란, 필수 항목 되묻기 |

먼저 가게 모드의 모드별 분기를 `ModeProfile`의 함수(대사 고정·검사·카드·체크리스트)로 모으는 정리를 하면, 매물 모드는 그 함수들을 채우는 일이 된다.

## 6. 단계별 계획

| 단계 | 내용 | 완료 기준(Gate) |
|---|---|---|
| L0 | 법령 원문 확인: 명시사항 세부기준 고시, 부당 표시·광고 고시, 영상 광고의 명시 방법(유권해석) | 필수 항목 목록과 표시 방법을 DECISIONS에 기록 |
| L1 | 모드 정리(가게 분기를 `ModeProfile` 함수로) + `listing` 모드·스키마·사무소 저장 | 취미·가게 테스트 그대로 통과, 모드 변경 불가 테스트 |
| L2 | 매물 입력 양식 + 필수 항목 되묻기 + 사진 종류 | e2e: 매물 입력 → 아이디어까지 |
| L3 | 대본 규칙: 가격·마지막 대사 고정, 금지 표현·숫자 검사 | 실제 Gemini로 매물 3건, 입력에 없는 숫자·과장 0건 |
| L4 | 매물 정보 카드 렌더 + 렌더 점검 | 1080×1920에서 카드 글자가 잘리지 않음(프레임 확인) |
| L5 | 체크리스트·설명란·커버 | e2e: 완성 화면에 필수 표시 확인 항목 |
| L6 | 실제 매물(본인 허락 받은 사진) 2~3건으로 끝까지 | 중개사 1명 이상 사용 후 의견 |

## 7. 결정 필요

- **D-1 대상:** 개업공인중개사 전용으로 할지(필수 표시 전제), 집주인 직거래도 받을지. 추천: 중개사 전용(직거래는 명시 의무 체계가 달라 문구가 갈린다).
- **D-2 첫 매물 종류:** 추천: 주거용(아파트·오피스텔·빌라·원룸)부터. 상가·토지는 항목이 달라 2차.
- **D-3 AI 영상:** 매물 사진에도 AI 영상을 허용할지. 추천: 끈다(방 크기·구조가 바뀌어 보이면 부당 광고에 가깝다). 가게 모드와 다르게 가는 이유를 기록한다.
- **D-4 소재지 공개 범위:** 동까지만(기본) / 단지명까지 / 정확한 주소. 법의 '소재지' 명시 수준과 개인정보 사이의 판단이라 L0 확인 뒤에 정한다.
- **D-5 커버에 가격:** 넣으면 클릭은 늘지만 가격이 바뀌면 커버도 다시 만들어야 한다.
- **D-6 상업 이용:** 가게 모드와 같은 미결정(D21 상업 이용) — Edge 음성·Gemini 무료 등급의 상업 이용 조건.
- **D-7 일괄 만들기:** 1차부터 넣을지, 1건씩으로 시작할지. 추천: 1건씩으로 시작, 사무소 정보 재사용만.

## 8. 성공 지표

- 입력부터 첫 완성까지 중앙값 5분 이내(가게 모드와 같은 기준).
- 실제 대본에서 입력에 없는 숫자·과장 표현 0건(검사 통과율과 경고 수를 metrics에 남긴다).
- 필수 표시 카드 누락 0건(렌더 점검).
- 중개사가 업로드한 영상 수, 다시 만든 비율.
