## 근거

- **D1.** 호스팅형은 GPU 서버 비용이 생겨 "비용 ₩0" 원칙과 충돌한다. 발표 자료의 제안과도 같다.
- **D2.** PRD의 M0는 Streamlit, M1은 Next.js라 2주짜리 화면을 버리게 된다. 계획서 G1을 참조한다.
- **D3.** 개발 PC는 RAM 8GB에 GPU가 없어 Ollama로는 3B급 모델만 돌릴 수 있고, 한국어 품질이 불확실하다. Gemini 무료 정책이 바뀔 때를 대비해 어댑터 교체 경로는 유지한다.
- **D4.** 개발 PC에 GPU가 없다(Intel UHD 620). PRD 리스크 표에서 "GPU 없는 사용자"의 가능성이 높다고 본 것과도 맞는다.
- **D6.** 실측에서 `order=viewCount` 검색이 "퇴근 후 홈트"에 어깨 운동 영상을 2위로 올렸다. 검색 순서를 바꾸면 조회수 높은 영상이 덜 잡히고, 사용자 수동 해제만으로는 기본 선택이 틀린다. LLM 판정은 쿼터 0, 호출 1회다.
- **D8.** MeloTTS는 PyTorch(수 GB)가 필요해 RAM 8GB 노트북에 부담이 크다. Edge-TTS의 리스크는 상업 이용 조건이고, MVP(로컬·비상업 베타)에서는 문제가 되지 않는다.
- **D11.** 실측 결과 3.8-flash 무료 등급은 프로젝트·모델당 **하루 20회**였다(`GenerateRequestsPerDayPerProjectPerModel-FreeTier`). 프로젝트 1편에 LLM 호출이 5~7회이므로 하루 3~4편이 한계다. 한도는 모델마다 따로라, 가벼운 작업을 경량 모델로 보내면 주 모델 호출은 1편당 2~4회(S3, S4 재시도)로 줄어 하루 5~10편이 된다. 일일 한도 429는 기다려도 풀리지 않으므로(retryDelay 약 19시간) 대기하지 않는다.
- **D12.** 2026-10 조사 결과는 다음과 같다. Cloudflare는 매일 10,000 Neurons를 무료로 준다(공식). 체험판 크레딧이 아니라 매일 다시 채워지는 한도라 ₩0 원칙에 맞는다. FLUX.1 schnell은 입력이 `prompt`·`steps`뿐이라(`additionalProperties: false`) 9:16과 seed를 지정할 수 없다. 그래서 multipart로 width·height·seed를 받는 klein 4B를 기본으로 한다(720×1280 = 6타일 × 26.05 ≈ 156 Neurons, 하루 약 64장). Gemini 이미지는 최근 자료상 API 무료 등급이 없다. Pollinations는 2026-07 무료 무키 등급이 종료됐다. Hugging Face는 월 $0.10 이하라 사실상 체험판이다. 무료 사진은 실제 사진이라 "내 체험" 이야기에 자연스럽다. 처음에는 Pexels로 정했지만, 2026-10-15 확인 결과 Pexels API 페이지에 **"New API key issuance is currently paused"** 공지가 있어 신규 키를 받을 수 없었다. 그래서 기본을 Pixabay로 바꿨다(무료 키 발급 가능, 60초당 100회). Pixabay 약관은 검색 요청을 24시간 캐시하고, 이미지를 직접 링크하지 말고 내려받아 쓰며, 출처를 표기하도록 요구한다. 어댑터가 이를 모두 지킨다. 식별 가능한 인물 사진은 초상권에 주의한다. 생성 이미지는 장면마다 인물이 달라지므로 프롬프트를 손·물건·공간 위주로 만든다.
  - **2026-10-21 갱신:** 생성 크기를 864×1536으로 올렸다(같은 6타일·156 Neurons). 더 큰 모델(klein 9B 장당 약 1,364, FLUX.2 dev 20스텝 장당 약 4,500 Neurons)은 무료 한도로 하루 영상 1편도 어려워 쓰지 않는다. 장면마다 다른 인물 문제는 '얼굴 피하기'만으로 막히지 않아(스타일 문구에 인물 클로즈업이 있으면 LLM이 따른다) 주인공 고정 묘사(subject)를 모든 인물 장면에 넣는 방식으로 바꿨다. 실측: 6장 모두 글자 없음, 같은 교복의 한국인 학생으로 이어짐.
- **D13.** 무료 Gemini 주 모델은 하루 20회라 하루 5~10편이 한계이고, 과부하·한도 소진 때 경량 모델로 대체되면 품질 경고가 붙는다. 무료 등급은 입력이 모델 개선에 쓰일 수 있고 상업적 이용이 제외된다. 사업화와 처리량을 위해 유료 모델을 쓸 수 있어야 하지만, 베타 사용자와 기본 경로는 지금처럼 돈이 들지 않아야 한다(D5 유료 플랜의 가치와 연결). 그래서 (1) 끄면 지금과 완전히 같고, (2) 켤 때는 사용자 키와 명시적 동의가 필요하며, (3) 하루 예산 상한이 있고, (4) 가벼운 작업은 계속 무료로 보낸다. 비용 가드 테스트는 없애지 않고 바꾼다: 유료 SDK import는 `app/adapters/llm/advanced/` 안에서만 허용하고, 기본 설정으로는 그 모듈이 로드되지도, 유료 어댑터가 만들어지지도 않음을 테스트로 고정한다. Claude는 OpenAI 호환 방식이 아니라 공식 `anthropic` SDK로 호출한다. 프롬프트가 작업당 약 1천 토큰이라 캐싱 최소 길이(모델별 512~4,096 토큰)에 못 미쳐 프롬프트 캐싱은 쓰지 않는다. OpenAI·OpenRouter는 같은 OpenAI 호환 형식이라 어댑터 하나(httpx)로 붙였다. 우리 스키마에는 기본값이 있는 선택 필드가 있어 OpenAI strict 모드(모든 필드 required)와 맞지 않으므로 `strict: false`로 보내고 Pydantic으로 다시 검증한다. OpenRouter는 `provider.require_parameters`로 구조화 출력을 지원하는 서버로만 보내고, 응답의 실제 청구액(`usage.cost`)을 기록한다. 모델·가격은 OpenRouter 공개 모델 목록(2026-10-20)으로 확인했다.
  - **실측 (2026-10-20, 같은 주제, S3·S4만 유료):** Claude Opus 5.5 — S3 21.4초, S4 27.4+21.1초(재생성 1회), $0.16, Gate 통과. Sonnet 5.5 — S3 9.9초, S4 15.6+9.4초, $0.063, Gate 통과. Haiku 5.5 — S3 13.0초, S4 19.7초(재생성 없음), $0.004, Gate 통과. 참고로 무료 Gemini(사고 low)는 S3 약 6초, S4 8~10초(회당)다. 즉 고급 모드는 **빠르지 않고**, 가치는 무료 한도·과부하 대체에서 벗어나는 것, 상업 이용, 분석 문장의 신중함(추정과 확인을 더 분명히 나눔)이다. Sonnet 5.5가 시간·비용·품질 균형이 가장 좋았고, Haiku 5.5는 비용이 거의 들지 않지만 결과 장면 대사가 약했다("달라진 점을 정리해볼게요"처럼 약속만 하고 보여 주지 않음). 처음에는 기본 모델을 각 제공자의 가장 높은 등급으로 두었으나, 아래 실측 뒤 **Anthropic·OpenRouter의 기본을 Claude Sonnet 5.5로 바꿨다**(Opus보다 약 2배 빠르고 비용은 40%, Gate 통과, 결과 대사가 더 구체적). OpenAI는 Terra가 재생성을 3번 해 근거가 약하므로 Sol로 둔다. 화면에 실측 비용을 보여 사용자가 고르게 한다.
  - **실측 (2026-10-20, OpenAI·OpenRouter):** GPT-5.6 Sol — S3 19.0초, S4 23.2+22.2초(재생성 1회), $0.118, Gate 통과. Terra — S3 8.7초, S4 회당 10~13초지만 재생성 3회로 48초, $0.077, Gate 통과. Luna — S3 13.0초, S4 11.1+8.2초, $0.004, Gate 통과. OpenRouter 경유 Claude Sonnet 5.5 — S3 13.7초, S4 17.4+9.8초, $0.068(직접 호출 $0.063과 비슷), Gate 통과. GPT 계열은 대사가 매끄럽지만 신중해서 결과 장면이 추상적이었고("과정과 움직임만 비교할게요", "미루는 마음부터 달라졌다"), 거의 모든 장면에 visual 요인을 붙였다. Claude Sonnet 5.5는 구체적인 결과("계단이 덜 힘들고")를 썼다. 7회 실측 모두 Gate 통과, 합계 $0.72. 1편 비용 순서: Haiku·Luna(1센트 미만) < Sonnet·Terra($0.06~0.08) < Sol·Opus($0.12~0.16).
- **D14.** 2026-10 검토 결과는 다음과 같다. Pixabay Music과 YouTube 오디오 보관함은 공식 API가 없어 자동으로 쓸 수 없다(웹 페이지 긁어오기는 약관 위반 소지). Jamendo API는 무료지만 상업 이용에 별도 라이선스가 필요하다. Freesound API는 무료 키로 CC0 음원을 찾을 수 있지만 사용자가 계정·키를 만들어야 하고, 효과음 위주라 30초 배경음악으로 쓸 만한 곡이 드물며, CC-BY는 출처 표기가 필요하다. MusicGen 같은 AI 작곡은 GPU가 필요해 개발 PC(D4)에서 돌릴 수 없다. 그래서 1단계는 의존성 없이(순수 파이썬 + FFmpeg 후처리) 분위기별 코드 진행·빠르기·악기(패드·아르페지오·베이스·킥·하이햇)로 합성한다. 목소리 아래에 -18dB로 깔리고 렌더가 사이드체인으로 덕킹하므로 단순한 음색으로 충분하다. 같은 프로젝트는 같은 곡(seed = 프로젝트 ID + variant)이라 다시 실행해도 바뀌지 않는다. 사용자가 고른 음악(끈 상태 포함)은 `AudioMix.locked`로 6단계를 다시 실행해도 유지한다.
  - **실측 (2026-10-23):** 분위기마다 30초 곡 합성 2.5~3.0초, -17.8 LUFS로 고름. 실제 프로젝트("영어 공부에 대한 Motivation")에서 S6 LLM(gemini-3.5-flash-lite, 무료 1회)이 `inspiring`을 골랐다. 렌더 25초, 장면 사이 무음 구간이 8곳 → 0곳으로 채워졌고 최종 음량은 같다(-13.6 LUFS).
- **D7.** `gemini-2.5-flash`는 목록에는 나오지만 신규 사용자에게 404를 냈다. 처음 받은 키는 선결제(prepay) 프로젝트 소속이라 402(크레딧 소진)가 났다. 결제가 연결된 프로젝트는 유료 등급으로 모든 호출이 과금되므로 ₩0 원칙과 충돌한다. `doctor.py --probe-llm`으로 확인한다.
